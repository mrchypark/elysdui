The existing web implementation. Go templates render Ely-inspired components as HTML; the SDUI adapter validates screen definitions and handles declared region updates.

Browse real rendered components, or author JSON in the browser-only playground. Static demos do not execute backend actions.

SwiftUI

Actual SwiftUI controls, without a WebView. The profile example covers local text editing, server validation, canonical save, retries and full-region replacement.

Original profile: seven types (region, form, stack, text, input, button and notice). The separate controls-v1 demo adds switch, checkbox and select for ten types. Not a general-purpose native renderer.

Jetpack Compose

Actual Compose controls for Android, using the same Go-resolved profile screen. Local drafts stay separate from acknowledged server state during validation and retries.

The same original seven-type profile and ten-type controls-v1 demo as SwiftUI. Full web catalogue coverage and a general native renderer are not implied.

The server decides.
The platform renders.

The standalone Go/htmx UI, semantic SDUI core and platform adapters have separate package boundaries. Share screen structure and intent without pretending every platform has the same components or runtime.

Read the SDUI architecture ↗
  1. 01

    Define and validate

    Versioned JSON describes typed components, bindings and named actions. The Go registry checks properties and composition before rendering.

  2. 02

    Resolve with server state

    Go resolves data bindings, conditions and stable-key repetition. The host application owns validation, action handlers and business rules.

  3. 03

    Render for the target

    The web adapter produces HTML. The native profile slice receives a resolved semantic tree for SwiftUI or Compose, with explicit unsupported states for capabilities it cannot handle.

  4. 04

    Reconcile the response

    Actions return through declared routes. Web updates replace a validated region; the native profile example uses revisions and request identity to preserve newer local edits.

A clear application boundary

Authentication, authorization, durable persistence and external services belong to the host application. The examples and static previews are not production infrastructure.
