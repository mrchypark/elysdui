# Workspace component API

Use `ui.Component{Chapter, Name, ID, Props}`. The parent resolver owns the outer wrapper and protected ID, Chapter, Kind, Variant and ComponentName. Supply a unique ID per instance. No example content is supplied by the production templates.

Common properties: optional `Title`, `Description`, `Disabled`, `Required`, `Name`, `Value`, `Action`, `ActionLabel`, and optional `ActionValue`. Workspace headers render only when the caller supplies Title or Description; component names are never shown as fallback metadata. `ws-action` accepts `Type` (button by default, submit inside editor forms). Caller strings are escaped. Read-only displays remain read-only.

## Editing and host payloads

CodeEditor and the source/query renderers use a contenteditable textbox with a named hidden input, not a textarea. Supply `Value` or `Lines[{Number,Text,Spans(Text,Tone),Folded,Inlay,Diagnostic(Severity,Message)}]`, plus `Language`, `Cursor`, and optional `Ruler`. CodeEditor optionally accepts `Breadcrumbs(Value,Label)`, `EditorTools(Action,Label,Pressed,Disabled)`, `CodeLenses(ID,Label)`, and `Minimap`; folds emit `toggle-code-fold`, lenses emit `run-code-lens`, tools emit `editor-tool`, and breadcrumbs emit `open-code-location`. The standalone `MiniMap` alias renders only the read-only minimap. QueryEditor additionally accepts `QueryColumns`, `QueryRows`, `QueryHistory(ID,Query,Status,Duration)`, and recursive `PlanSteps(ID,Label,Rows,Cost,Detail,Children)`; local result filter/sort emit `sort-query-results`, history controls emit `rerun-query` with `historyId` and `query`; plan controls emit `select-query-plan-step`. Every custom event keeps `id` for the workspace root identity. Lines initialize the visible code when supplied. The hidden field is synchronized on initialization, input and submission; line numbers are excluded. `Name` defaults to code. QueryEditor can use Name=query. Submit emits Action or save-code with current plain code in native `FormData.get(Name)`.

RichTextEditor uses an escaped contenteditable document with caller `EditorTools` (heading, list, link, quote, and code actions); local selection formatting updates the serialized hidden field. BlockEditor uses caller `Blocks` and `BlockMenu`, with local menu insertion and block editing before it submits the serialized text. The legacy CommentThread path (without `Threads`) uses a contenteditable textbox initialized with escaped `Content`. Name defaults to content. Submit emits Action or save-content with current serialized content. Serialization preserves paragraph, line-break, emphasis, list, heading, quote and code tags, removes attributes, unwraps unsupported tags, and drops active script/style/embed elements. It does not trust caller HTML. Both editor forms block empty Required content before the base dispatcher runs, expose an alert and set aria-invalid. Disabled/Readonly editor surfaces cannot submit edits.

MarkdownEditor uses a native named textarea initialized from `Value`. Initial preview uses the shared safe Goldmark GFM helper. Real textarea input emits preview-markdown with `source`; it does not locally parse text or pretend that preview succeeded. The gallery host POSTs source to /components/markdown-preview and replaces preview nodes with the safe MarkdownRenderer response. Production hosts must bind the same action or provide their own renderer. The local preview becomes plain source text until the host replaces it with a safe rendered response.

MarkdownRenderer uses a read-only article with safe GFM from `Value`; raw HTML and dangerous URL schemes are disabled by the shared helper. TableOfContents and DocumentOutline aliases generate links from the actual rendered headings. Heading IDs start with the wrapper ID. ReadingProgress measures its own scroll region with a native progress element.

DocumentViewer and OfficePreview render caller `Pages` as local thumbnail/page rails with page selection, zoom, and DocumentViewer find controls. EpubReader uses caller `Chapters` for a local chapter rail, reading position, and type-size controls. Content stays escaped text. PrintPreview renders caller pages and local paper, orientation, margin, and copies fields; only its typed submit requests host printing.

Rich editable forms have Bold, Italic and Code controls. Select text in the instance, then apply formatting. These controls use native DOM Range extraction/insertion without execCommand. The current safe serialization is returned through the named hidden field. Active content and attributes are removed; limits of 100 nesting levels and 10000 nodes produce a visible error and block submission rather than silently truncating.

Canvas backgrounds support pointer pan with a real CSSOM transform combined with zoom. Whiteboard adds a Draw mode: native pointer samples create an SVG polyline; draw-stroke emits points, color and width for host persistence. A stroke is bounded to 5000 samples. Pointer cancel removes an unfinished local stroke. Shape movement and keyboard selection remain instance-local. CommitGraph can derive SVG edges from Nodes' Parents IDs; absent parents are ignored. ThreeWayMerge choices now populate the merged textarea from the selected caller version before user edits and host submission.

The base module owns generic action dispatch: forms include native FormData and values, buttons include their value and any containing form data. Custom operations supply additional fields through emit. Selection/edit/filter/canvas changes use instance-local ely:change. Consumers must read current editor data from FormData, not original props or submitter labels. No component performs provider calls, executes arbitrary code, or reports provider success without host results.

## Coverage and verification limits

Nine chapter templates and synthetic caller-data fixtures cover 96 primary names: editor 12, terminal 5, git 7, debug 6, documents 18, collab 8, files 20, canvas 9, devtools 11. Focused Go tests validate rendering, escaping, native domain semantics, aliases and editor form landmarks. Gallery-only browser checks validate current submitted editor/query content, rich serialization, required errors, method selection, real Markdown preview responses, Markdown alias navigation/progress and upgraded domain interactions. The parent runs browser checks on all aliases.

All 96 primaries have semantic renderers and shared controls. Their checks require actual controls and test caller data, current submitted fields, local selection/formatting/insertion, link/disclosure semantics or computed canvas transforms and stroke geometry. The gallery audit checks each registered qualified name using two independent instances.

Remaining domain limits: code editing does not provide language parsing, folding, multicursor editing, Vim keymaps or a language server; completion candidates and code actions are caller/host supplied. Complex table/image/math block editing, mentions and link-format dialogs are not implemented by the basic rich formatter. Legacy canvas callers do not enable the source-scene APIs described below. Automatic graph layout and pressure-sensitive brush input remain host boundaries. Live collaboration, invitation permissions, persistent review/resolve state, printing/export, debug expression evaluation and task execution require host backends. Aliases share the primary API except the explicit variant controls documented above; alias-specific advanced features must not be inferred from catalogue names.
