# Data family API

The data family renders `data`, `lists`, `tables`, `charts`, `finance`, and `dashboard` catalogue stories. Each instance uses its wrapper `ID` and keeps interaction state inside that root.

All stories accept caller-owned values only. List-oriented stories accept `Items`, with `Value`, `Label`, `Description` or `Detail`, `Leading`, `Trailing`, `Selected`, and `Disabled`. Table stories accept `Columns` (`Label`) and `Rows` (`Cells`). Trees use recursive `Items[].Children`.

Charts require caller geometry. Line charts use `Points` and optional `GridPath`. Areas use `AreaPath` and `Bars`. Pie charts use `Segments[].Path`; scatter charts use point `X/Y/R`; radar charts use polygon point strings; heatmaps use `Cells[].Level`; treemaps use positioned items; Sankey charts use `Links[].Path` and positioned `Nodes`; waterfalls and histograms use `Bars`; Gantt charts use `Tasks[].Left/Width`; networks use `Edges` and positioned `Nodes`; bullet charts use `Value`, `Max`, and `Target`. There is no fallback chart series.

RowGrouping accepts Groups. Each group has Value, Label, and canonical table Rows. Each group starts expanded and has its own disclosure control. Callers with a flat Rows[].Group collection must group it before rendering.

TreeTable accepts recursive top-level Rows. Each row has Label, Cells, and optional Children with the same shape. Every node has independent disclosure state. Node IDs derive from the component ID and the row index path, never caller text.

PivotTable accepts Measures. Each measure has Value, Label, Selected, and canonical table Rows. Selecting a measure emits ely:change. Submitting emits the pivot-measure action with the native measure payload. The host can select a measure with ely:data detail {measure}. The component does not calculate aggregates.

Candlestick charts use `Candles` with wick and body geometry. Depth charts use `BidPath` and `AskPath`. Indicator overlays use `Paths`. Drawing tools use caller-owned `Tools` and `Drawings`. Order books use `Bids` and `Asks`. QR and barcode output uses the caller `Value` through the shared encoders. `Meter` accepts `Label`, `Min`, `Max`, `Value`, and `ValueText`.

`Badge` accepts `Items` (`Label`, optional `Tone` and `Dot`) plus optional `Counts` (`Icon`, optional `Count` or `Dot`, `Tone`). `Tag` items accept `Value`, `Label`, optional `Icon`, `Tone`, and `Removable`; removing a tag updates the local collection and emits `tag-remove`. `Avatar` accepts either one avatar or `Avatars`; an avatar can provide `Initials`, optional `ImageURL`, `Icon`, `Size` (`xs` through `xl`), `Presence`, and `Caption`. `AvatarGroup` accepts `Items`, or gallery-style `Groups` with shown `Items`, `More`, and optional `Size`. `Statistic` accepts a single `Label`, `Value`, and `Trend`, or `Statistics` KPI cards and compact `Metrics`. `DescriptionList` accepts `Items`, or `Columns` with `Layout` (`lined` or `stacked`) and `Items`. Timelines, activity feeds, and changelogs use caller `Items`. `PropertyGrid` accepts `Fields` (`Name`, `Label`, `Value`, `Required`, `Disabled`). `Spreadsheet` accepts `Cells`. `OrderEntry` accepts `Symbol`, `Quantity`, and `Price`. `LeverageSlider` accepts `Value` and `Max`. `CurrencyConverter` accepts `Value`, `From`, `To`, `Currencies` (`Value`, `Label`, optional positive `Rate` relative to a shared base), and optional host-provided `Converted`. When both selected currencies supply rates, the component previews their offline conversion locally; without rates, Convert remains a host action for fresh market data. `RealtimeChart` accepts `Samples`. `Carousel` accepts `ImageURL`, `ImageAlt`, and `Caption`.

Native changes emit `ely:change`. Selection, reordering (including native drag), filtering, column visibility, range updates, carousel navigation, chart samples, drawing-tool selection, sorting, checkbox-tree changes, and alert acknowledgement also emit `ely:change` with action-specific detail. Data-family forms emit host actions through `data-ely-submit`: `save`, `save-row`, `order`, `convert`, `screen`, `indicators`, and `pivot-measure`. The order form validates symbol, positive quantity, and non-negative price before it asks the host to review the payload. It does not report a completed transaction.

`List` rows can provide `LeadingStyle: "avatar"` for an initials avatar and `ListStyle: "divided"` for a compact divided list. `SelectableList` supports caller `Multiple`, pointer selection, Cmd/Ctrl toggles, Shift ranges, Home/End, Up/Down, Space, Cmd/Ctrl-A, and typeahead; each change emits selected caller values. `SortableList` keeps caller `Items` in DOM order and supports native drag and Alt+Up/Down, emitting `reorder`. `SwipeableListItem` accepts per-item `Actions` (`Value`, `Label`, optional `Tone`); a left swipe reveals them, and an action emits `swipe-action` without deleting caller rows. `VirtualList` accepts the caller's visible `Items` plus `Total`, `Start`, and `End`; scrolling reports a local `virtual-range` but never fabricates unseen rows. `InfiniteList` accepts caller `Items`, `Cursor`, `Loading`, and `Done`; it enters local loading state and emits `load-more`, while the host supplies another page. `Tree` and `FileTree` disclose recursive `Items[].Children`; focused nodes support Left/Right disclosure, Home/End, Up/Down, and first-letter focus. `FileTree` adds a local Filter files field that limits visible caller paths. `CheckboxTree` gives each recursive node the caller `Name`; branches use native disclosure controls, node `Disabled` is honored, and checking a node updates enabled descendants while ancestors show their native indeterminate state. `TreeSelect` includes descendants with visible depth. `Outline` uses flat `Items` with `Value`, `Label`, `Level` (1–6), and optional `Selected`; choosing a heading emits `ely:select-heading` with `headingId` set to the caller `Value` (the root `id` remains the component identifier). `GroupedList` uses `Groups[].Label/Items`.

`Dashboard Grid` accepts `Widgets` with stable `Key`, explicit `Label`, optional `Subtitle`, `Value`, optional chart `ViewBox`/`Points`, and optional grid `X`, `Y`, `W`, `H`. Arrow moves emit `ely:dashboard-layout` with every tile coordinate. Optional `Filters` contain `Name`, `Label`, and `Options` (`Value`, `Label`, optional `Selected`); `RefreshOptions` uses the same option shape. Their changes emit `ely:dashboard-filter`; an optional `RefreshAction` renders a host action button. `UptimeBar` accepts `Services` with `Label`, `Value`, and `Samples` (`State`, optional `Label`). `AlertList` items accept `Key`, `Label`, `Source` or `Detail`, `Since`, `Severity`, and `State`; acknowledgement emits `ely:acknowledge` with the caller key and leaves the row visible. `EventStream` items accept `Kind`, `Tone`, `Time`, and `Label`; optional `Kinds` provide caller-owned filter-chip labels. Its chips emit `ely:change` with `event-filter`, and Pause emits `event-pause`; incoming events remain host-owned.

`Meter` can also render caller `Gauges` (`Label`, `Value`, `Suffix`, `Percent`) and `UsageParts` (`Label`, `Value`, `Text`, optional `Tone`). `UptimeBar` also accepts optional `ServiceStatus` (`Label`, `Value`, `State`) and `HealthChecks` (`Label`, `State`, `Detail`). `AlertList` can include an optional `Incident` with `Severity`, `Phase`, `Title`, `Detail`, and dated `Updates`.

`RowExpansion` accepts `Columns` and keyed `Rows`; Edit opens a real row form whose save action is `save-row` and includes `key` plus the edited `value`; Cancel closes it locally. `DataGrid` cells are native editable grid cells and emit `ely:change` with `grid-edit`. Spreadsheet cells are caller-owned display values; formula evaluation remains with the caller or host. Canonical finance tables (`OrderBook`, `TimeAndSales`, `PositionTable`, `DividendTable`, `Screener`, and `OptionChain`) use explicit caller `Columns` and `Rows`; `OrderBook` separates `Bids` and `Asks`, while `OptionChain` also accepts `Symbol` and `Expiry`. `Watchlist` uses list items and filters them locally. `Ticker` entries use `Label`, `Value`, `Change`, optional `Tone`, and optional SVG `ViewBox`/`Points`; `MarketOverview` uses the same quote fields. `PortfolioSummary` accepts `Statistics` and `Holdings` (`Label`, `Value`, `Text`).

Dense table variants keep their semantic caller data separate from the shared table toolbar: `Spreadsheet` accepts `Columns` and row `Label`/`Cells`; `TreeTable` accepts recursive `Rows` with optional `Depth`; `PivotTable` accepts `Columns` plus per-measure `Rows`; `HeatmapTable` continues to accept flat `Cells` and can use `HeatmapRows` for labeled matrix rows. Finance records support caller `Spread`, bid/ask `Level`, `Ladder`, `Summary`, `Orders`/`OrderColumns`, option `Greeks`, market-tile `Span`, calendar `Forecast`/`Actual`, and converter `Wallet`/`Transfers`. `EconomicCalendar` emits the `calendar-event` `ely:action`. `EventStream` accepts host input via `ely:event` (`kind`, `label`, optional `time`), queues it while paused, and flushes on Resume. Dashboard tiles now support pointer movement, an accessible resize corner, and existing keyboard movement; both emit `ely:dashboard-layout`.

`PropertyGrid` also accepts grouped inspector data through `Groups` (`Label`, optional `Collapsed`, and `Fields`); fields can use `Options`, `Range` (`Min`, `Max`, `Step`), or `Switch`/`Checked`, and an optional `Preview` renders a local frame controlled by `width`, `height`, `direction`, `opacity`, and `visible` field names. `Timeline` accepts `Timelines`, each with `Items` (`Time`, `Label`, optional `Detail`, `Icon`, `Tone`). `ActivityFeed` items use `Actor`, `Initials`, `Verb`, `Object`, optional `Detail`, and `Time`. `Changelog` accepts `Releases` (`Version`, `Date`, optional `Latest`, `Summary`, and grouped `Changes` with `Kind`, `Tone`, and `Items`). `Carousel` and `Gallery` use caller `Items` with `Value`, `Label`, `ImageURL`, and `ImageAlt`; Carousel supports four-or-more slides, dots, pointer, and arrow-key navigation through `navigate`. `DirectoryListing` accepts `Path` (`Value`, `Label`) and rows with `Folder`, `Size`, and `Modified`; folder presses emit `directory-open` with both `value` and `folder` set to the caller value, and path presses emit `directory-path`. `Spreadsheet` can use `Columns` for lettered grid headers and rows for title, header, formula, and total cells. A stream keeps at most 500 queued or rendered events; a blank active-kind selection shows every event, matching the reference filter semantics.

`Comparison` accepts `Plans` (`Label`, optional `Featured`) and feature `Features` (`Label`, `Values`), keeping the comparison matrix caller-owned. `DataTable` accepts ordinary table `Columns` and `Rows`; rows may additionally provide `Initials`, `Trend` SVG points, and a numeric `Quota` for the native person, sparkline, and meter cells. With `Paged: true`, its `PageSize` selects a local page window over every supplied row; Previous, Next, search, filtering, sorting, column visibility, and density remain local. `ColumnPinning` uses caller `Columns` and `Rows`; its first column remains sticky while the matrix scrolls. `RowGrouping` uses the same column schema plus `Groups` (`Value`, `Label`, `Rows`); it renders one shared toolbar and each group can fold locally, emitting `toggle-group` with its caller value.

`BeforeAfter` accepts `BeforeURL`, `AfterURL`, accessible image alternatives, and a `Value` percentage. Its in-image divider supports pointer drag, press-to-position, and Left/Right movement; changes emit the caller `compare` action. `Watermark` accepts `Watermark`, `Title`, `Description`, and optional `Read`; Mark as read and Unmark as read update only local presentation and emit `watermark-read`. `QRCode` accepts a `Codes` collection (`Label`, `Value`, `Format` of `qr`, `code128`, or `ean13`); barcode aliases use their rendered `.Variant` and caller `Format`. `Stars` accepts read-only `Ratings` (`Value`, `Max`, `Text`, optional `Size`, and star `Fill` values from 0 to 100) for full and fractional score rows.

### VirtualTable: supplied-row windowing

The Go component's `TableSource: true` path accepts caller `Columns[].Label` and
`Rows[].Cells`, with optional `Rows[].Key`, `RowHeader`/`Rows[].Label`, `Label`, `Empty`, `Error`, `Disabled`,
and `VirtualTotal`. After initialization it attaches only a fixed-height 32-pixel
row window plus four overscan rows on each side. A 300-pixel scroll region keeps
the column headings visible. Arrow keys, Page Up/Down, Space/Shift-Space, and
Home/End scroll the focused region. Rows retain their original DOM identity and
caller order; there is no local sorting, selection or editing contract here.
`Disabled` removes the region from tab order and blocks keyboard commands;
read-only pointer scrolling remains available. `Error` displays the caller's
escaped error instead of mounting a controller. Empty input displays `Empty` or
"No rows.". On complete-root replacement/removal, lifecycle cleanup removes listeners and
observers and restores all rows. Replace the complete component root with HTMX
`outerHTML`; a retained-root `innerHTML` swap stops the family controller before
the mutation and mounts it again afterwards, so the virtual table is rebuilt from
the new markup.

Only supplied rows contribute to scroll geometry and accessible row counts.
`VirtualTotal` is descriptive metadata: a larger number explicitly reports that
remaining rows were not supplied, and never creates phantom rows or fetches
records. The complete supplied rows are server-rendered and retained in browser
memory; this bounds the attached DOM after mount, not transfer size, initial HTML
parsing, or total memory. Without JavaScript all supplied rows remain readable.
Use bounded caller data; this is not a claim of million-row scalability.

This follows the reference's local fixed-height `DataTable.virtualized()` design
(`src/tables/table.rs` and `examples/gallery/pages/tables/core.rs` at upstream
`da3fdca`). Remote paging, source URLs, asynchronous range responses, and source
error/retry protocols have no implemented host contract. The strict SDUI registry exposes these local-data properties using lower
camel case (for example, `tableSource`, `virtualTotal`, and `rows[].key`); it has
no remote-source or asynchronous window-response schema. Existing `TableSource: false` rendering
remains the ordinary table fallback, without a virtualization claim.
